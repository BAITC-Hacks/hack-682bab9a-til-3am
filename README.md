# HackAlem AI — чат-ассистент ekt.kz

Прототип ИИ-консультанта для каталога ekt.kz. Архитектура MVP, границы компонентов, API-контракт и ограничения текущих данных описаны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Данные для прототипа

- `dataset/api_products.json` и `dataset/api_products_page2.json` — две страницы каталога, всего 40 уникальных товаров.
- `dataset/api_products_detail.json` — подробная карточка товара `515291`, включая характеристики и остатки по складам.

- `demo_data/stock_overrides.json` — **синтетические** остатки для нескольких товаров без detail-карточки (например, `027230` с нулевым остатком), чтобы показать сценарий «нет в наличии → аналог». Реальные остатки из выгрузки не перезаписываются; в чате такие остатки помечены «синтетический остаток демо».
- `demo_data/faq.json` — **условия демомагазина** (оплата, доставка, минимальная партия, возврат). Это допущение прототипа, а не правила ekt.kz; ответ ассистента помечает это явно.

Аналоги подбираются без LLM, по признакам из названия: тип изделия, ток, серия, полюса, отключающая способность, бренд. Кандидаты должны быть того же типа и с подтверждённым остатком. В обосновании перечислено, что совпадает и что отличается.

Это тестовая выборка, а не полная синхронизация с ekt.kz. В ней нет сертификатов и справочника условий покупки. Для реального изменения корзины нужен согласованный API сайта и привязка к сессии пользователя.

## Локальный запуск

Нужны Python 3.10+ и Node.js 18+.

Backend:

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
python -m pip install -r backend/requirements.txt
uvicorn app.main:app --app-dir backend --reload
```

LLM (необязательно): скопируйте `backend/.env.example` в `backend/.env` и укажите `LLM_API_KEY`.
Рекомендуем Google Gemini: бесплатный ключ можно получить на https://aistudio.google.com/apikey, модель хорошо понимает казахский.
Подойдёт любой OpenAI-совместимый провайдер (Groq, OpenRouter, NVIDIA). Ключ не добавляйте в Git.

LLM только понимает свободный текст на русском и казахском (намерение, товар, количество, город, язык) и переформулирует готовый ответ на языке клиента. Все числа в ответе модели сверяются с ответом из данных: если модель изменила или добавила цифру, показывается исходный ответ. Без ключа, при ошибке или таймауте backend работает в детерминированном режиме.

Frontend в отдельном терминале:

```bash
cd frontend
npm install
echo VITE_API_MODE=live > .env.local   # работать с backend, а не с локальным mock-каталогом
npm run dev
```

Откройте `http://localhost:5173`. Проверка backend: `http://localhost:8000/api/v1/health`. Vite проксирует `/api` на `127.0.0.1:8000`.

## Что умеет прототип

| Требование кейса | Как реализовано | Пример запроса |
|---|---|---|
| Наличие, характеристики, сертификат | Поиск по ID, артикулу, коду производителя и словам из названия (синонимы: «автомат» → «АВ»). В ответе цена, остаток по городу или складам, ключевые характеристики. Противоречие 160/250 А показывается явно. Если сертификата нет в данных, ассистент так и отвечает и даёт ссылку на карточку | `Есть 027228 в Алматы?`, `покажи сертификат` |
| Аналоги при нулевом остатке | [analogs.py](backend/app/assistant/analogs.py): тот же тип изделия, подтверждённый остаток; в обосновании совпадения, отличия и напоминание проверить совместимость | `Нужен 027230` |
| Условия покупки | Условия демомагазина из `demo_data/faq.json` с явной пометкой; кратность берётся из карточки, если она есть | `условия доставки и оплаты?`, `минимальная партия?` |
| Корзина только после подтверждения | Ассистент создаёт одноразовое предложение (5 минут, привязано к сессии). Корзина меняется только по кнопке «Да, добавить» или фразе «да, добавь». Текстом подтверждается только последнее предложение. Остаток проверяется повторно с учётом того, что уже в корзине | `добавь 2 штуки` → `да, добавь` |
| Ссылка на корзину | После добавления: состав корзины, сумма и ссылка на неё | — |

Контекст диалога хранится в сессии: `а в Нур-Султане?` и `добавь 2` относятся к последнему обсуждаемому товару.

## Архитектура

```
frontend (React + Vite) ──/api──▶ FastAPI (backend/app/main.py)
                                   ├─ assistant/orchestrator.py  разбор запроса, ответ только из данных
                                   │   ├─ retrieval.py            поиск товара
                                   │   ├─ analogs.py              объяснимые аналоги
                                   │   └─ llm_client.py           NVIDIA NIM (опционально, только разбор запроса)
                                   ├─ catalog.py / inventory.py   выгрузка ekt.kz + синтетический оверлей остатков
                                   ├─ faq.py                      условия демомагазина
                                   └─ cart/adapter.py             MockCartAdapter: предложение → подтверждение → проверка остатка
```

Агент не может изменить корзину: он возвращает только намерение, а предложение, подтверждение и проверку остатка выполняет backend. Цены и остатки берутся только из каталога, LLM их не генерирует.

## Ограничения

- Реальные остатки в выгрузке есть только у товара `515291`. Для остальных наличие «не уточнено», а не 0. Синтетические остатки для сценария с аналогами помечены в ответе и на карточке.
- Условия оплаты и доставки — допущения демомагазина, а не правила ekt.kz. Сертификатов в выгрузке нет.
- Сессии, предложения и корзина хранятся в памяти процесса и сбрасываются при перезапуске. Настоящая корзина ekt.kz подключается отдельной реализацией `CartAdapter`.
- Вложения (фото, Excel, Word, PDF) и ответы на казахском языке не реализованы.
- Платёжные данные не запрашиваются и не хранятся.
